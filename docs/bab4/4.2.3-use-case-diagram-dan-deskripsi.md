### UC-03 -- Menerima Rekomendasi Kos

| Field | Keterangan |
|---|---|
| **ID Use Case** | UC-03 |
| **Nama Use Case** | Menerima Rekomendasi Kos |
| **Aktor** | Pengguna (Calon Penyewa) |
| **Deskripsi** | Use case inti penelitian ini: sistem menghasilkan daftar Top-N kos yang dipersonalisasi menggunakan pendekatan hybrid filtering (Content-Based + Collaborative Filtering), dengan penanganan otomatis kondisi cold-start. Rincian teknis alur ini dijabarkan pada Activity Diagram Gambar 4.4 (lihat `docs/diagrams/skripsi/gambar-activity-uc03-rekomendasi.puml`). |
| **Prakondisi** | Pengguna sudah memiliki profil preferensi (telah menyelesaikan UC-02). |
| **Alur Normal** | 1. Pengguna membuka halaman Beranda.<br>2. Sistem (RecommendationService) mengambil profil pengguna dan menghitung jumlah interaksi ber-rating miliknya.<br>3. Sistem menentukan status pengguna: jika jumlah interaksi ber-rating = 0, status cold-start (alpha = 1); jika tidak, status warm-start (alpha = 0.6).<br>4. Untuk setiap kos, sistem menghitung Skor_CB (ContentBasedFilter) dari kemiripan vektor profil dan atribut kos.<br>5. Jika warm-start, sistem juga menghitung Skor_CF (CollaborativeFilter) dari kemiripan pengguna dengan pengguna lain.<br>6. Sistem menggabungkan Skor_hybrid = alpha x Skor_CB + (1-alpha) x Skor_CF (SwitchingWeightedCombiner).<br>7. Sistem mengurutkan seluruh kos berdasarkan Skor_hybrid secara menurun dan mengambil Top-N (10) teratas.<br>8. Sistem menampilkan daftar rekomendasi beserta status cold-start/warm-start dan alasan tiap kos kepada pengguna. |
| **Alur Alternatif** | 5a. Pada kondisi cold-start, langkah 5 dilewati sepenuhnya (Skor_CF = 0), sesuai mekanisme switching.<br>Alur pembaruan: setiap kali pengguna memberi rating (UC-05) atau mengklik kos (UC-04), status cold-start/warm-start dan rekomendasi berikutnya dapat berubah karena data interaksi bertambah. |
| **Pascakondisi** | Daftar Top-N kos yang dipersonalisasi ditampilkan kepada pengguna, siap dilanjutkan ke UC-04 (Melihat Detail Kos). |
